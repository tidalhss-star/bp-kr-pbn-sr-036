Apache Superset RC3 삭제와 2.0 배포 전의 변화

## 구체적 니치 콘텐츠 작성

### 주제
Apache Superset 2.0 릴리스 전 PyPI에서 삭제된 RC3 빌드의 취약점과 삭제된 실제 이유

### 맥락
오픈소스 도구 취약점/변경점 / Kubernetes deprecated API

#### 검색 의도 대응
- RC3 빌드가 삭제되었을 때, Apache Superset 2.0 릴리스에 대한 공식 발표 또는 배포 내용은 어디에서 찾았는지?
- PyPI에서 RC3 빌드를 삭제한 이유는 무엇인지?

#### 구체성 원칙
- Apache Superset 2.0 릴리스 전 RC3 빌드가 설치되었던 시점의 최신 버전 정보와 취약점을 비교했을 때, 어떤 부분이 달라졌는지?
- 삭제된 RC3 빌드에서 발생했던 특정 오류 코드와, Superset 2.0에 추가된 오류 확인 방법이 무엇인가?

### SRE 엔지니어 시점에서 서사(narrative) 전개

#### 조건
Apache Superset은 오픈소스 데이터 관리 도구로 사용되고 있습니다. RC3 빌드는 개발 중단되었지만, Superset 2.0으로 이전되었습니다.

#### 절차
- Apache Superset의 RC3 릴리스 전 배포 문서를 찾아보았습니다.
- PyPI에서 해당 RC3 버전이 삭제된 이유를 파악했습니다.

#### 관찰 포인트
RC3 빌드는 주요 기능 개선과 함께 새로운 취약점도 발생하였습니다. 이를 확인하기 위해 Superset 2.0의 배포 문서와 RC3 버전의 오류 코드를 비교했을 때, 두 버전 간에 큰 차이가 있었습니다.

#### 예외 및 고려 사항
- Apache Superset은 Kubernetes API에서 deprecated된 것처럼 보였습니다.
- 하지만 이는 사실이 아닙니다. Superset 자체는 Kubernetes와 관련 없었지만, 배포 시 Kubernetes API를 사용하였습니다.

### 한 문장 반복 및 해석

RC3 빌드에서 발생한 취약점과 RC3 빌드가 삭제되었을 때 Superset 2.0으로 이전된 이유는 주로 새로운 버전에 대한 개선사항과 함께 악意大나 보안 문제를 제거하기 위한 것임을 알 수 있습니다.

### 가독성 문단 구조

- Apache Superset의 RC3 릴리스 전 배포 문서를 찾아보았습니다.
- PyPI에서 RC3 버전이 삭제되었음을 확인했습니다.
- RC3 버전과 Superset 2.0 간 비교를 통해 취약점과 오류 코드가 달라진 점을 발견하였습니다.

### 소제목 활용

#### 소제목 1: Apache Superset의 RC3 배포 문서 분석
Apache Superset의 RC3 릴리스 전 배포 문서를 찾아보았습니다. 이 문서에서는 주요 기능 개선사항과 함께 취약점 발생 사항이 언급되었습니다.

#### 소제목 2: PyPI에서 RC3 버전 삭제 이유 파악
PyPI에서 Apache Superset의 RC3 빌드가 삭제되었음을 확인했습니다. 이는 배포 문서를 통해 알 수 있었습니다.

#### 소제목 3: RC3와 Superset 2.0 간 비교
RC3 버전과 Superset 2.0을 비교했을 때, 취약점과 오류 코드에 큰 차이가 있음을 발견하였습니다.
